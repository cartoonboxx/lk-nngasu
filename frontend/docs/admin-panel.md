# Административная панель lk-nngasu

## Вход и выход

Из `frontend` запустить `npm run dev`, открыть `/authorization`, ввести логин `root` и пароль `admin`. В режиме разработки форма принимает логин без проверки формата email. Успешный временный вход открывает `/admin`, который перенаправляет в `/admin/requests`.

Адаптер `src/pages/auth/admin-demo.ts` работает только при `import.meta.env.DEV`. Он открывает исключительно локальные примерные данные, не вызывает административные API и не предоставляет серверных прав. Пароль не сохраняется и не выводится в логи. В `sessionStorage` записывается только маркер сеанса, поэтому обновление страницы сохраняет текущий раздел до закрытия вкладки. Если хранилище недоступно, доступ действует до обновления страницы.

Нажать StudentCard внизу навигации → «Выйти из демо-режима». Переход на `/authorization` или выход с административных маршрутов также очищает маркер; возврат через историю браузера снова требует входа. Постоянного фиктивного сеанса в localStorage нет. Старые `localStorage.isAdmin`, маркер `lk-nngasu-admin-demo` и параметр `?demo=1` больше не открывают панель. В production временный вход отключён.

Серверная авторизация обычных пользователей в существующей форме ещё не реализована: до доработки форма не отправляла запросов. Её поля, регистрация и разделы кабинета сохранены, а отправка теперь показывает состояние отсутствующей интеграции. При подключении реального входа временный адаптер нужно удалить и проверять подтверждённый сервером `is_admin`/сеанс. Бэкенд, действующие контракты и серверные проверки прав не изменялись.

## Разделы

| Маршрут | Сценарии |
| --- | --- |
| `/admin/requests` | Поиск и фильтры, сортировка даты, пагинация, просмотр паспорта и СНИЛС, уточнение документов, выбор роли вручную, одобрение с созданием пользователя, отклонение без указания причины с подтверждением. Повторное решение не создаёт дубликатов. |
| `/admin/users` | Создание и изменение, поиск по ФИО/email, фильтры, паспорт, СНИЛС, группа, зачётка, староста, кафедра, аватар, блокировка/восстановление с подтверждением. Административные права доступны только для чтения; блокировка последнего активного администратора запрещена. |
| `/admin/structure` | Группы, направления, кафедры, дисциплины, семестры, аудитории: поиск, создание, изменение, архивирование с проверкой зависимостей. |
| `/admin/courses` | Группа и семестр, назначения дисциплин, разные преподаватели и типы нагрузки, плановые часы, проверка ссылок при изменении/удалении. |
| `/admin/schedule` | Двухнедельный шаблон Пн–Сб, временная сетка/список, фильтры по группе/преподавателю/аудитории, CRUD, проверки интервалов; создание занятия нажатием на пустую ячейку с заполнением дня, пары, недели, семестра и выбранной группы или аудитории. Сетка всегда содержит 7 пар; нажатие на ячейку заполняет день и номер пары. В форме выбирается пара вместо ввода времени. Шкала времени соответствует исходной таблице студентов, включая седьмую пару 18:35–19:55. Исходные и сохранённые занятия не изменяются при загрузке; существующее время сохраняется при редактировании других полей. Плюс показывается только в пустой ячейке, занятие открывается для редактирования. |
| `/admin/news` | Черновик, предпросмотр, необязательная обложка, закрепление, публикация, снятие с публикации, архивирование и удаление с подтверждением. |

Отдельного дашборда нет: стартовая страница — рабочая очередь заявок. Демонстрационная шапка, восстановление данных, история действий и ссылка «Личный кабинет» удалены. Ссылки в панель из студенческой навигации удалены. Функциональность истории не переносилась в другие разделы.

## Компоненты и стили

- `AdminPage.vue` отвечает за контент, общие состояния загрузки/ошибки/успеха. `components/AdminNavigation.vue` — за меню, сворачивание, мобильное меню и аккаунт.
- Навигация переиспользует CSS Modules существующих DesktopNavBar/MobileNavBar, а контент — HomeLayout: ширина 280 px, свёрнутая 80 px, те же отступы и мобильный breakpoint. Самостоятельных значений ширины админского navbar нет.
- Пункты меню — штатный NavTab с необязательным `to`, который передаётся в BaseTab и рендерится через RouterLink; прежние вкладки остаются кнопками. В нижней части используется StudentCard без вымышленных учебных полей. На телефоне — нижняя навигация NavigationItem и штатный Modal для остальных разделов.
- Все выпадающие списки — штатный Select. Его строковые значения переводятся в числовые ID рядом с обработчиками; обязательность ссылок дополнительно проверяет стор. Переключатели — StyleTab, поля текста — TextInput, флаги — Checkbox; IconButton используется с `round`.
- Кнопки, модальные окна, шрифты, радиусы, цвета и отступы используют UI Kit и дизайн-токены. Числовые поля, время и выбор файла остаются нативными: штатный TextInput не поддерживает соответствующие типы. Таблица и карточка занятия используют существующие паттерны, так как отдельного универсального компонента таблицы/карточки в UI Kit нет.
- Формы остаются рядом со своими страницами. Общие AdminTable, AdminDialog, UserFields и AdminImage используются несколькими сценариями. Кнопка и диалог копирования шаблона убраны из расписания.

## Данные и граница интеграции

`admin.types.ts` содержит модель шести разделов, `admin.data.ts` — фабрику вымышленных записей, `admin.repository.ts` — локальное чтение/сохранение, `src/stores/admin.ts` — CRUD и проверки связей. Стор больше не управляет доступом, не ведёт историю и не содержит функции восстановления.

Данные продолжают сохраняться по существующему техническому ключу `lk-nngasu-admin-demo-v1`, чтобы не потерять созданные ранее записи. Этот идентификатор не выводится в интерфейсе. При чтении берутся только актуальные поля модели, устаревшие дополнительные поля прежнего снимка не попадают в состояние и последующие сохранения. Нет кнопки сброса/восстановления. Ошибка хранилища отображается явно, при неудачном сохранении данные в памяти не подменяются. Локальные изображения — PNG/JPEG/WebP до 2 МБ; несколько крупных изображений могут исчерпать квоту браузера.

Паспорт и СНИЛС переносятся из заявки в карточку при одобрении. Проверяется формат: паспорт — 10 цифр слитно или `45 09 123456`, СНИЛС — 11 цифр слитно или `112-233-445 95`; подлинность документов и контрольное число СНИЛС не проверяются. У старых локальных записей отсутствующие поля заменяются пустыми строками без удаления данных; перед одобрением заявки или сохранением карточки документы нужно заполнить. Регистрация пока не отправляет заявки в панель, её серверная интеграция не реализована.

Локальный контракт `load/save` снимка не является будущим HTTP-контрактом: реальная интеграция потребует отдельных команд сущностей и серверной пагинации. Не передавать демонстрационный снимок в настоящий API.

На бэкенде уже есть `app_user`, отдельные `student`/`teacher`, справочники, `course_offering`, `workload`, `lesson`, `file` и часть административных CRUD. DTO ролей пока не отражают все независимые признаки. Для заявок и новостей нужны согласованные API/сущности; архивирование справочников и изменение курсов/нагрузки тоже не полностью соответствуют текущим endpoint. Для аватара и обложки необходима привязка через существующую модель file.

Клиентская история удалена вместе с AuditPage.vue, маршрутом, типом, исходными данными, фильтрами, записью изменений и стилями просмотра. В текущих миграциях и модулях бэкенда сущности/эндпоинтов административной истории не обнаружено; серверные системные логи и middleware не затрагивались. Новые зависимости для истории не предлагаются.

Оставшиеся ограничения: одна роль при одобрении заявки, возможность двух учебных профилей в карточке; консервативная проверка пересечений обычных занятий; нет модели потоков, разовых исключений и полного календарного баланса часов. Публичная лента новостей пока использует собственные примеры. Эти ограничения существовали до рефакторинга.

## Проверка

`npm run build` проверяет типы и production-сборку, `npm run lint:check` — линтеры. Тесты и тестовая инфраструктура не добавляются согласно AGENTS.md.

Ручные сценарии: неправильный пароль не открывает панель; root/admin открывает; обновление сохраняет текущий раздел; выход и кнопка браузера «Назад» не возвращают доступ; query-параметр и старые флаги не обходят вход. Пройти шесть разделов, фильтры и формы Select, одобрение/отклонение, пользователя, справочники, нагрузку, создание занятия через пустую ячейку в заполненной и пустой сетке, черновик/публикацию. Проверить прокрутку модалки вверх и вниз после включения и выключения флага «Староста группы». Проверить сворачивание навигации, ширину относительно обычного кабинета, мобильное меню и отсутствие горизонтального выхода страницы. Production-сборка должна отклонять временный вход.
