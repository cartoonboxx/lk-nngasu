# Административная панель

Вход выполняется через `/authorization`. Административные маршруты требуют
`is_admin=true` из серверного ответа. Профиль и access-токен хранятся в памяти;
после перезагрузки сессия восстанавливается через HttpOnly refresh-cookie.

Панель использует существующие API. Демонстрационные записи, генератор данных,
чтение и сохранение снимка админпанели в localStorage удалены. Старые локальные
данные не импортируются на сервер и не отображаются. Тема интерфейса сохраняется
отдельно, она не является источником данных панели.

## Заявки

`/admin/requests` загружает `GET /registration-requests` с параметрами
`q`, `status`, `sort`, `limit`, `offset`. Поиск, фильтры, сортировка и пагинация
выполняются сервером. Общий счётчик ожидающих заявок берётся отдельным запросом
с `status=pending&limit=1` из `meta.total`; он не зависит от текущего фильтра.
Кнопка «Обновить» перечитывает список. Запоздавшие ответы предыдущих запросов
не заменяют результат нового поиска.

Перед рассмотрением карточка перечитывается через `GET /registration-requests/:id`.
ФИО уточняет администратор, группу и кафедру форма получает из серверных справочников.
Паспорт и СНИЛС доступны только в оперативной памяти страницы, не в localStorage.
Одобрение отправляет `POST /registration-requests/:id/decision` с `decision=approve`
и `user`: ФИО, документы, ровно одна учебная роль; вторая передаётся как null.
Пароль берётся сервером из заявки. Отклонение отправляет только `decision=reject`.

После успешного решения список и счётчик обновляются. Если заявку уже рассмотрел
другой администратор, показываются серверная ошибка и актуальное состояние.
Поле `reviewed_by` читается как объект `{id, name}`. После одобрения ссылка на
пользователя открывает его серверную карточку в разделе пользователей.

## Остальные разделы

| Маршрут | Источник и действия |
| --- | --- |
| `/admin/users` | `/users`: серверный список; полная карточка с документами загружается через `/users/:id`. Создание — POST с отправкой приглашения, редактирование и блокировка — PATCH. Локальная загрузка аватара удалена. |
| `/admin/structure` | `/groups`, `/departments`, `/specializations`, `/catalog/subjects`, `/semesters`, `/rooms`: чтение с `include_archived=true`, создание, изменение, архивирование. |
| `/admin/courses` | `/courses`, `/courses/:id/workloads`, `/workloads/:id`: назначения дисциплин и нагрузка. При редактировании курса меняется только дисциплина, как разрешает API. |
| `/admin/schedule` | `/schedule/lessons?semester_id=…`: загрузка шаблона, создание, изменение, удаление занятий. Пересечения окончательно проверяются сервером. |
| `/admin/news` | Управление временно недоступно: серверных методов записи нет. Демонстрационные новости и локальные действия удалены. |
| `/admin/administrators` | Серверные приглашения и назначение прав, доступны только владельцу с `can_manage_admins=true`. |

Справочники, пользователи и курсы загружаются постранично до исчерпания `meta.total`,
поэтому формы не ограничены первыми 50/200 записями. В заявках применяется отдельная
серверная пагинация по 8 строк. Для других списков сохраняются фильтры и пагинация
интерфейса поверх загруженных серверных данных.

Изменения отправляются отдельными командами сущностей, общий снимок в API не передаётся.
Сообщение об успешном сохранении появляется после успешного ответа сервера.
При выходе и смене аккаунта данные панели очищаются; результаты старых загрузок
не подставляются в новую сессию.

Создание владельца и настройка приглашений описаны в
[инструкции администратора](../../backend/docs/admin-access.md).
