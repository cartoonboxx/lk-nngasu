# Личный кабинет ННГАСУ

## Локальная разработка

```sh
docker compose up -d --build
```

Фронтенд доступен на http://localhost:5173, Adminer — на http://localhost:8080.
Изменения исходников фронтенда подхватывает Vite.

## Развёртывание на сервере

На сервере нужны Git, Docker Engine и плагин Docker Compose.
Node.js и npm устанавливать на сервер не требуется.

Склонируйте репозиторий и перейдите в его каталог:

```sh
git clone <URL-репозитория> lk-nngasu
cd lk-nngasu
```

Запустите сборку и приложение:

```sh
docker compose -f compose.prod.yaml up -d --build --wait
```

Docker собирает Vue-приложение с проверкой TypeScript, затем копирует `dist`
в образ nginx. Проверка типов и сборка запускаются последовательно, чтобы
снизить пиковую нагрузку на память. В итоговом контейнере работает nginx.
Контейнер доступен только на самом сервере по `http://127.0.0.1:8081`.
Публичные порты 80 и 443 обслуживает уже установленный на сервере nginx.
Вложенные адреса Vue Router можно открывать напрямую.

`compose.prod.yaml` используется самостоятельно: объединять его с `compose.yaml`
не нужно. У продакшена отдельное имя проекта, исходники с сервера в контейнер
не монтируются. Эта конфигурация публикует текущий фронтенд; backend пока
не реализован, поэтому PostgreSQL и Adminer в неё не включены.

### Подключение к существующему HTTPS nginx

Схема запросов: браузер → nginx сервера (HTTPS, 443) → `127.0.0.1:8081`
→ nginx контейнера (HTTP, 80) → файлы Vue.

1. Проверьте контейнер с самого сервера:

```sh
curl -fsS http://127.0.0.1:8081/healthz
curl -fsS http://127.0.0.1:8081/dashboard
```

Первая команда должна вывести `ok`, вторая — HTML с `<div id="app"></div>`.
`Healthy` проверяет только `/healthz` внутри контейнера, а не публичный HTTPS.

2. Найдите активный конфиг серверного nginx:

```sh
sudo nginx -T
```

В выводе перед каждым конфигом указан путь к файлу. Найдите `server`, который
слушает `443 ssl` и обслуживает ваш адрес в `server_name`. При обращении по IP
может выбираться другой, стандартный server. Открывайте домен, соответствующий
HTTPS-конфигу и сертификату.

3. Сохраните резервную копию найденного файла и отредактируйте его.
Замените существующий `location /` внутри нужного HTTPS `server` содержимым
`deploy/nginx-location.conf`. Не добавляйте второй `location /` в тот же блок.
Сохраните `listen`, `server_name`, пути к SSL-сертификатам и остальные
необходимые настройки. Если есть отдельный `location /assets/`, раздающий
старые файлы с сервера, его тоже нужно направить в контейнер.

**`proxy_pass http://127.0.0.1:8081` находится только в nginx на сервере.**
В `frontend/nginx.conf` контейнер раздаёт собранные файлы через `try_files`.
Внутри контейнера адрес `127.0.0.1` указывает на сам контейнер, а не на сервер.

4. Проверьте и примените изменения серверного nginx:

```sh
sudo nginx -t && sudo systemctl reload nginx
```

Изменения nginx на сервере не требуют пересборки Docker.

5. Проверьте ответ HTTPS, заменив `example.org` своим доменом:

```sh
curl -fsS https://example.org/dashboard
```

Если локальный адрес отдаёт Vue, а публичный — приветственную страницу nginx,
проверьте выбранный `server` и DNS домена. Можно проверить конкретный сервер
с сохранением правильных Host и TLS SNI (подставьте домен и IP):

```sh
curl --resolve example.org:443:SERVER_IP https://example.org/dashboard
```

Если нужно временно исправить только конфиг nginx внутри уже работающего
контейнера без повторной сборки Vue, после исправления файла выполните:

```sh
docker compose -f compose.prod.yaml cp frontend/nginx.conf frontend:/etc/nginx/conf.d/default.conf
docker compose -f compose.prod.yaml exec frontend nginx -t
docker compose -f compose.prod.yaml exec frontend nginx -s reload
```

Это временное изменение контейнера. Для сохранения при его пересоздании
позже соберите исправленный образ. Изменение только `nginx.conf` теперь
не сбрасывает кеш этапа сборки Vue в `Dockerfile.prod`.

### Обновление

В каталоге проекта на сервере:

```sh
git pull --ff-only
docker compose -f compose.prod.yaml build frontend
docker compose -f compose.prod.yaml up -d --no-build --wait
```

Во время сборки предыдущая версия продолжает работать. Если сборка завершилась
с ошибкой, не выполняйте следующую команду. При успешном обновлении контейнер
пересоздаётся, поэтому возможен короткий перерыв в доступности. Автоматического
отката эта схема не выполняет.

### Состояние и логи

```sh
docker compose -f compose.prod.yaml ps
docker compose -f compose.prod.yaml logs --tail=100 -f frontend
```

Healthcheck проверяет ответ nginx по `/healthz`.

Для остановки продакшена:

```sh
docker compose -f compose.prod.yaml down
```

Файлы `.env` исключены из контекста сборки. Если появятся настройки Vite,
передавайте необходимые публичные `VITE_*` параметры явно на этапе сборки:
они попадают в браузерный код и не подходят для секретов.
